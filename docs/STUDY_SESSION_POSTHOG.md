# Session 2 completion tracking

Set `NEXT_PUBLIC_POSTHOG_KEY` and `NEXT_PUBLIC_POSTHOG_HOST` in the frontend deployment, then rebuild. The key is a PostHog project key (public client key), and the host must be the matching project's ingestion host. `next.config.ts` proxies requests through the first-party path `/dfr-collect` to avoid browser content blockers; set `POSTHOG_INGEST_HOST` only if the server-side ingestion host differs from `NEXT_PUBLIC_POSTHOG_HOST`. No event is sent when the public key is missing.

The browser console always logs `[D-Friend/PostHog] event queued for ingestion` for each Session 2 event. During `npm run dev`, the same sanitized event payload is also printed in the dev-server terminal as `[D-Friend/PostHog][browser]`; this endpoint returns `404` outside development. Set `NEXT_PUBLIC_POSTHOG_DEBUG=true` while verifying a browser to additionally enable the PostHog SDK's own request diagnostics. "Queued" does not prove successful ingestion: confirm the event in the matching PostHog project, and look for browser/network blocks such as `ERR_BLOCKED_BY_CLIENT`.

The frontend identifies the authenticated student by internal user ID only. Autocapture, pageviews, pageleave, and session recording are disabled. Events contain IDs, timestamps, lesson kind, and counts; they contain no answers, chat, names, or email.

| Event | When |
| --- | --- |
| `study_session_started` | First successful entry into a backend Session 2 `session_id` |
| `study_session_progressed` | Backend reports a higher completed problem count |
| `study_session_completed` | Backend session state reaches all problems complete |
| `study_session_ended_early` | Backend accepts the early close request |
| `study_session_expired` | Backend accepts automatic close after the server-issued 60-minute deadline, with problems still unfinished |
| `study_session_left` | Student leaves the Session 2 page before completion or early close; this is a diagnostic signal, not the abandonment definition |

Each event includes `session_id`, `lesson_id`, `lesson_kind`, `problem_count`, and server-issued `started_at`. The start event also includes `attempt_window_minutes = 60`. The AI service issues `started_at` and `expires_at` when Session 2 begins; Nest also returns `server_now` so the UI can offset the device clock. A return to the same backend `session_id` retains the deadline. The UI shows the remaining time and requests close when it reaches zero; the AI-service expiration sweep closes sessions even if the student leaves the tab. The server, not PostHog or the browser clock, owns the final completion status.

For the primary metric, group by `session_id`. Count a session as completed when a `study_session_completed` event arrives. Count it as abandoned when an early/expired close event arrives without completion, or when its start event is at least 60 minutes old without completion. A still-active attempt is excluded from the denominator. A `study_session_left` event alone does not make a session abandoned: the student may return within the hour. The dashboard uses the timestamp of the captured start event for its 60-minute fallback; the AI service's server-issued `expires_at` remains authoritative for closing the product session. Report counts and the completion/abandonment percentages together. Filter by `lesson_id` or `lesson_kind` when comparing lessons.

PostHog dashboard: [D-Friend | Session 2 completion](https://us.posthog.com/project/625575/dashboard/2130475). The seven-day ratio tile includes observed early/expired closes immediately and starts with no completion after 60 minutes; active attempts remain out of the denominator. It also accepts a terminal event without a matching start, since browser delivery can lose one event. The 30-day daily chart shows recorded terminal events only, so inferred silent abandonment appears in the ratio tile but not that chart. The metric counts a backend-completed session even if the student skipped every problem; use assessed-problem evidence separately to measure actual work or mastery.

E2E check on 2026-09-24: a demo student produced `study_session_ended_early` for one Session 2 attempt and `study_session_started`, four `study_session_progressed`, and `study_session_completed` for another. PostHog ingested those events, the ratio tile rendered 1 completed / 1 abandoned / 50%, and the daily chart rendered one completed and one ended-early series. The second attempt skipped all four problems, so this check verifies session completion telemetry, not successful assessment. The 60-minute unattended-expiry branch was not exercised live.

The 60-minute rule now closes the learning session in the product. The two-hour Nest Redis TTL is only a cache retention limit, not the learning deadline. An expired partial session is stored as `EXPIRED_PARTIAL`, not `EVALUATED`; unattempted problems remain unassessed. Browser event delivery can be lost if a student is offline, blocks PostHog, or clears site storage. For a pilot decision, reconcile PostHog with backend `student_session_started`, `session_completed`, `session_expired` and AI `mastery_sessions.completion_status`; a closed early session has its own event/status. The AI sweep can complete before the Nest submission is synced, so backend reporting needs a recovery close request on next visit; do not assume PostHog alone is an authoritative denominator.
